# 0001. Монорепозиторий

**Статус:** принято

## Контекст
Три сервиса (web, core-api, ai-service), маленькая команда, контракты между
сервисами часто меняются.

## Решение
Один репозиторий, сервисы лежат в `services/`, общие контракты — в
`contracts/`, инфраструктура — в `infra/`.

## Последствия
- Изменение API и его использование попадают в один PR.
- `docker compose up` поднимает всё сразу.
- CI нужно фильтровать по путям, чтобы не собирать всё на каждый коммит.
