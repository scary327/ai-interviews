# 0002. Авторизация: JWT RS256, выдаёт только core-api

**Статус:** принято

## Контекст
Пользователь обращается к двум бэкендам. Логику авторизации не хочется
дублировать, но ai-service должен знать, кто к нему пришёл.

## Решение
- core-api выдаёт access-токены (JWT, RS256, ~15 мин) и refresh-токены
  (httpOnly cookie).
- Публичный ключ доступен на `/api/.well-known/jwks.json`.
- ai-service проверяет подпись по JWKS и кеширует ключ. Приватного ключа у
  него нет.

## Последствия
- Выдать токен может только core-api: даже если утечёт ai-service, подделать
  токен не получится.
- Ротация ключей — через `kid` в JWKS.
- Сервис-к-сервису ходит с отдельным `INTERNAL_API_TOKEN`, а не с
  пользовательским JWT.
